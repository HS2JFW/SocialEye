# SocialEye — Design Spec (v1.0)

> ระบบ AI Agent เฝ้าติดตามข่าวและโซเชียลมีเดีย เพื่อวัดว่าสะท้อนคุณธรรม 5 ประการ (พอเพียง · วินัย · สุจริต · จิตอาสา · กตัญญู) อย่างไร

> [!IMPORTANT]
> ทุกหน้าจอและทุกรายงานต้องระบุว่าเป็น **"ดัชนีสะท้อนจากสื่อออนไลน์"** ซึ่งไม่ใช่ดัชนีคุณธรรมทางการของศูนย์คุณธรรม

## 1. เป้าหมายและผู้ใช้
| หัวข้อ | ข้อตกลง |
|---|---|
| ผู้ใช้หลัก | หน่วยงานรัฐ ใช้ติดตามภาพรวมและทำรายงานเชิงนโยบาย และใช้แจ้งเตือนประเด็นร้อนเพื่อจัดแคมเปญได้ด้วย |
| สิ่งที่วัด | **สะท้อน (Reflect)**: เนื้อหาแสดงพฤติกรรมเชิงบวกหรือลบในแต่ละด้าน + **ความคิดเห็นสาธารณะ**: sentiment ของคอมเมนต์ |
| กรอบนิยาม | คุณธรรม 5 ประการของศูนย์คุณธรรม ตามแผนปฏิบัติการด้านการส่งเสริมคุณธรรมแห่งชาติ ระยะที่ 2 (พ.ศ. 2566–2570) |
| ภาษาและพื้นที่ | ภาษาไทย ระดับประเทศ **และรายจังหวัด** |
| ระดับงาน | Production |

| Google News | RSS ค้นตาม keyword | 1 |

| Pantip | crawl หน้าเว็บสาธารณะ ปฏิบัติตาม `robots.txt` จำกัดความถี่ ระบุ User-Agent ของหน่วยงาน และไม่ล็อกอิน | 4 |

- ดึงข้อมูล **ทุกชั่วโมง** สรุปรายวัน รายสัปดาห์ และรายเดือน
- ปริมาณที่คาดไว้คือ 3,000–10,000 ชิ้นต่อวัน และกรองความเกี่ยวข้องแบบราคาถูกก่อนส่งให้ LLM วิเคราะห์เต็มรูปแบบ

## 3. วิธีให้คะแนน
### 3.1 รายชิ้น (ใช้ LLM)
ประเมิน **แต่ละด้านแยกกันอย่างอิสระ** โดยให้ผลดังนี้

| ฟิลด์ | ค่า |
|---|---|
| `relevant` | bool |
| `polarity` | −2 … +2 |
| `confidence` | 0–1 |
| `rationale` + `evidence_quote` | เหตุผลสั้น ๆ + ข้อความที่ยกมาจากต้นฉบับ |
| `flags` | `satire`, `unverified`, `opinion` |
| `province` | สถานที่เกิดเหตุที่ดึงจากเนื้อหา (77 จังหวัด หรือ "ระดับประเทศ") |
| `comment_sentiment` | sentiment ของคอมเมนต์ แยกต่างหาก ถ้ามีคอมเมนต์ |

- **rubric** (`docs/rubric.md`): แต่ละด้านมีนิยาม ตัวบ่งชี้เชิงบวกและเชิงลบด้านละ 5–8 ข้อ ตัวอย่างข้อความของแต่ละระดับคะแนน และกฎสำหรับเคสกำกวม เช่น ข่าวจับคนรับสินบน = สุจริต − และวินัย + ต้องให้ **ผู้เชี่ยวชาญด้านคุณธรรมของหน่วยงานอนุมัติ** ก่อนใช้งาน
- **dynamic few-shot**: ค้นตัวอย่างจาก golden set ที่คล้ายกับเนื้อหาใหม่มากที่สุด 3–5 ชิ้น แล้วใส่ลงใน prompt

### 3.2 การรวมเป็นดัชนี
- น้ำหนักของแต่ละชิ้น = reach (ยอดวิว เอนเกจเมนต์ หรือความน่าเชื่อถือของสำนักข่าว) × confidence และถ้าติดธง `unverified` ให้ × 0.5
- แปลงเป็นสเกล **0.00–5.00** ด้วยสูตร: score = ((x̄ + 2) / 4) × 5 โดย **2.50 = กลาง**
- แสดงเป็น time series รายวัน พร้อมปริมาณการพูดถึง ส่วนคะแนนรวม 5 ด้านแสดงเป็นตัวเลขเสริมเท่านั้น
- **รายจังหวัด**: แสดงเป็นแผนที่ choropleth ถ้ามีเนื้อหาน้อยกว่า 30 ชิ้นในช่วงที่เลือก ให้ขึ้นว่า "ข้อมูลไม่เพียงพอ" และต้องบอกผู้ใช้ว่าคะแนนนี้คือคุณธรรมของ *เหตุการณ์ที่เกิดในจังหวัดนั้น*
- เฟส 2 ขึ้นไป: เปิดตัวเลือก calibration เทียบกับดัชนีทางการรายปีได้

### 3.3 การรับประกันคุณภาพ
- **ศูนย์ติดป้าย**: Analyst แก้ป้ายที่ AI ให้ได้ เพื่อสร้าง golden set **300–500 ชิ้นก่อน go-live**
- **หน้าวัดความแม่นยำ**: เทียบ AI กับคนอย่างต่อเนื่อง โดยต้องได้ **agreement ≥ 0.7** จึงจะ go-live

## 4. ความสามารถของ AI Agent
| Agent | หน้าที่ |
|---|---|
| Issue Agent | จับกลุ่มเนื้อหาเป็นประเด็นด้วย embedding clustering และเขียนสรุปรายวันและรายสัปดาห์ |
| Chat Agent | ตอบคำถามพร้อมอ้างแหล่งที่มา ถ้าค้นไม่พบให้ตอบว่า "ไม่พบข้อมูล" ห้ามเดา |
| Investigator Agent | เมื่อพบประเด็นร้อน ให้ขยาย keyword และค้นข้อมูลเพิ่มโดยอัตโนมัติ |
| Advisor Agent | ร่างข้อเสนอแนะเชิงนโยบายหรือแนวทางรณรงค์ ซึ่ง **ต้องให้คนตรวจก่อนเผยแพร่** |

### 4.1 RAG
- **LightRAG** ใช้ `Neo4JStorage` เก็บกราฟ และใช้ `PGVectorStorage` / `PGKVStorage` / `PGDocStatusStorage` เก็บข้อมูลใน PostgreSQL ตัวหลัก
- ป้อนเข้า LightRAG **เฉพาะเนื้อหาที่ผ่านการกรองว่าเกี่ยวข้องแล้ว และสรุปประเด็นรายวัน** โดยต้องปกปิดชื่อบุคคลทั่วไป (pseudonymize) ก่อนป้อน
- เครื่องมือของ Chat Agent:
  - `graph_query` (LightRAG): ใช้กับคำถามเชิงความสัมพันธ์และภาพรวมประเด็น
  - `search_content`: hybrid search บน pgvector ร่วมกับ full-text ที่ตัดคำด้วย PyThaiNLP รวมผลด้วย RRF และกรองตามวันที่ จังหวัด ด้านคุณธรรม และคะแนน
  - `query_index`: ดึงตัวเลขดัชนีและสถิติจาก SQL
- การแบ่ง chunk: 1 ชิ้นต่อ 1 chunk ถ้ายาวเกิน ~800 token ให้ตัดเป็นหลาย chunk ที่ซ้อนทับกันเล็กน้อย
- Embedding: ใช้โมเดลที่มีใน LiteLLM (`embeded`)

## 5. การแจ้งเตือน
- **เงื่อนไข** (Admin ปรับค่าได้ และทุกเงื่อนไขมี cooldown กันแจ้งซ้ำ):
  1. ดัชนีด้านใดด้านหนึ่งเปลี่ยนเกิน ±0.30 ภายใน 24 ชั่วโมง เมื่อเทียบกับค่าเฉลี่ย 7 วัน
  2. มีประเด็นใหม่ที่ปริมาณการพูดถึงพุ่งขึ้นจนได้ z-score > 3
  3. มีเนื้อหาที่ได้ polarity −2 และมี reach สูงมาก
- **ช่องทาง**: Email, LINE Official Account (ผ่าน Messaging API) และในหน้า dashboard
- **แจ้งเตือนระบบ**: เมื่อใช้งบ LLM ถึง 80% และเมื่อ pipeline ล้มเหลวเกิน 2 รอบติดกัน

## 6. หน้าจอและรายงาน
- **หน้าจอ**: ภาพรวม · แผนที่จังหวัด · ประเด็นร้อน · รายละเอียดเนื้อหา · Chat · ศูนย์ติดป้ายและหน้าวัดความแม่นยำ · รายงาน · Admin (แหล่งข้อมูล, keyword, ผู้ใช้, เงื่อนไขแจ้งเตือน, Wisesight import)
- **รายงาน**:
  - รายสัปดาห์: PDF 2–3 หน้า AI ร่าง แล้ว Analyst ตรวจก่อนกดเผยแพร่
  - รายเดือน: PDF + DOCX
  - Export ข้อมูล: CSV/Excel
  - ทุกฉบับใช้ฟอนต์ TH Sarabun และส่งทาง Email ให้รายชื่อที่กำหนด

## 7. ผู้ใช้ ความปลอดภัย และ PDPA
- **บทบาท**: Admin / Analyst / Viewer
- **การล็อกอิน**: ใช้ **Authentik** (ติดตั้งใน Coolify) เป็น OIDC SSO พร้อม 2FA
- **PDPA**:
  - เก็บข้อความต้นฉบับและ vector ของข้อความ 90 วัน แล้วลบ (ใช้ `adelete_by_doc_id` สำหรับข้อมูลใน LightRAG)
  - คะแนนและสถิติที่รวมแล้ว รวมถึงสรุปประเด็น เก็บถาวร
  - ปกปิดชื่อบุคคลทั่วไป ส่วนชื่อบุคคลสาธารณะและสำนักข่าวเก็บไว้ได้
  - ไม่สร้างโปรไฟล์รายบุคคล
  - ให้ DPO ตรวจทานก่อน go-live
- **Secrets**: เก็บใน `.env` ซึ่ง gitignore ไว้ และตั้งเป็น environment variables ใน Coolify
